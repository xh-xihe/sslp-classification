# SSLP Workbench 手动验收指南

日期：2026-09-29。说明使用中文，网页按钮使用实际英文名称。

入口：https://sslp-explorer-class36.xh-xihe.chatgpt.site

本轮验收对象是英文研究工作台的现有功能。浏览器精确计算、一次新的 Lean 内核检查、
全文 formalization 是三个不同的验收对象。网页通过下面的功能检查不等于后两者完成。

请建立专门的 QA 项目；不在已有正式研究项目中做丢弃修改和冲突测试。
基础流程可预留约 30–45 分钟；Lean 运行和模型环境排查单独计时。

## 准备与记录

- 用拥有此私有 Site 访问权的账户登录；当前没有开放给任意审稿人访问。
- 建议先在 Windows 桌面浏览器以 100% 缩放打开。若看到旧版中文界面，先 Ctrl+F5。
- 每项填写：通过 / 失败 / 环境阻塞 / 未测试。环境阻塞不算通过，也不等于数学反例。
- 每次修改后，只有收到 `Project saved to your account.` 才认为保存成功。
- 浏览器当前会保留临时草稿；仅按刷新看见同样内容，不能证明项目已存入账户。
- 记录浏览器、窗口尺寸、项目名、输入文件、Run 编号、点击顺序和实际提示。

## A01 — 英文界面与工作区

打开页面，应看见 SSLP Workbench、项目侧栏，以及 Code / Circuit / Checks / Compare /
Notebook / Certificates 六个工具入口。无需按论文顺序解锁工具。

检查所有产品按钮、提示、对话框与错误信息是否为英文。自填笔记、浏览器自身提示、
历史材料原文不是产品界面翻译的判据。缩窄窗口并尝试 200% 缩放，检查按钮是否可点击、
文字是否重叠；长表格可在表格内滚动，不应把整页撑出屏幕。

失败例：白屏、一直停留在 Opening research workspace、按钮遮挡、中文产品提示。

## A02 — 创建基准项目

点击 From a template。Project name 填 `QA-main-20260929`，Starting point 选
`Six-qubit transversal phase code · Class 36`，点击 Create project。

若出现丢弃未保存修改的提示，先确认那只是可丢弃的临时页面；正式研究内容先保存或导出。

Code 页应显示 6 qubits、K = 2、Target d ≥ 3，两个逻辑码字各有 12 个非零项。
点击 Save project，等待账户保存成功提示。

## A03 — 正确输入的精确检查

点击 Run exact checks，得到 Run 1。

| 字段 | 预期 |
| --- | --- |
| Orthonormal basis | Passed |
| KL scalar matrices | 154 / 154 |
| Target d ≥ 3 | Calculation passed |
| Diagonal logical action | Established；余数 (0,4)，模 5 |
| Lean kernel | Not run in browser |

选择 Pauli operator = I，矩阵应为单位矩阵。点击矩阵元检查贡献项与 Exact sum。
点击 Export report，保留文件。该 JSON 应声明 `kernel_status: not_run`。
本指南生成测试期望时只运行了精确计算，没有运行你这次页面中的 Lean。

## A04 — 有意制造失败，验证结果不会沿用

返回 Code，选 ψ0，找到 |000000⟩ 所在行，点击一次 × −1。

重新运行之前，右侧 CURRENT INPUT 应变成 Not checked 或 Not established 前的待检查状态；
若查看旧 Run 1，必须提示它是历史输入，不能仍把旧结论标为当前输入的结果。

再次点击 Run exact checks，得到 Run 2。

| 字段 | 预期 |
| --- | --- |
| Orthonormal basis | Passed |
| KL scalar matrices | 136 / 154 |
| Target d ≥ 3 | Not established |
| Diagonal logical action | Established，仍是 (0,4) |
| First failure | X1X6 |

点击 First failure，应看到矩阵 [[0,1/5],[1/5,0]]；网页可把 1/5 写成 `(1)/5`。
点击非对角元，展开贡献项，Exact sum 应为 1/5。

这是检测失败应有的正常表现。若仍显示 154/154，或把矩阵中的 1/5 显示成零，才是软件缺陷。

## A05 — 比较与恢复

进入 Compare：Baseline 选 Run 1，Candidate 选 Run 2。
两个输入都应规范正交；KL 计数应分别为 154/154 与 136/154。
Changed amplitudes 应只列 ψ0 |000000⟩。Lean kernel 两列都应是 Not run。

点击 Restore baseline input，回到 Code。恢复的是输入；不能把不同输入的结果自动移给它。
点击左侧 Run 1 可重新查看该快照的计算，或者再次运行当前输入。

## A06 — 电路和门参数

恢复基准输入后进入 Circuit，保留 Layer power = 1。
点击 Play layer，应逐步显示 Applied gates，从 0 到 6。
完整六个门作用后，Total probability 约为 1，规范输入的泄漏应接近 0
（浮点显示允许约 1e-10 的舍入误差，不要求文本必须恰好是 0）。

调整 θ、φ，检查逻辑输入与振幅预览更新。点击不同支持点，查看位串、相位与所选振幅；
勾选 Show all 64 states，并展开 Encoding matrix V。矩阵应有 64 行、两个逻辑列。

将 q5 的相位指数从 2 改为 1，再运行精确检查：KL 仍应为 154/154，但 Diagonal logical
action 不再建立。原因是修改物理门没有修改码字。然后把 q5 改回 2。

该支持检查是逻辑基中对角作用的充分测试；失败本身不证明任意逻辑基下都不保持码空间。
当前电路显示横向相位层和编码矩阵，不应宣称已经给出了经过证明的基础门编码器。

## A07 — 保存、重新载入和导出

进入 Notebook，写入 `Acceptance note: saved on 2026-09-29.`，点击 Save project。
确认成功后，点击右侧 Reload saved project。项目标题、笔记、当前输入与各个 Run 快照应保留。
重新载入时当前 Checks 面板可以为空；点击历史 Run 会从其保存输入重新计算。

进一步检查账户持久化：从一个独立新窗口手工打开网址，登录同一账户，从项目列表载入
QA-main-20260929。不要仅复制原标签页，因为浏览器可能连临时草稿也一起复制。

点击顶部 Export，得到整个项目 JSON；另可用 Export code JSON 导出当前码。
保存原项目后，用 Import code or project 导入刚导出的项目并点击 Validate and import。
它应成为新的 `(import)` 副本，包含笔记和快照，不覆盖原项目，也不导入虚构认证状态。

## A08 — 论文模板之外的输入

本目录包含三个可直接导入的文件。操作：先保存当前项目，然后点击 Import code or project，
选择文件，点击 Validate and import，再点击 Run exact checks。
每次从侧栏导入码文件都会创建新项目；如果要在同一项目中切换候选，应使用 Code →
Edit full definition 粘贴 JSON 并点击 Apply definition。

| 文件 | 输入 | 预期 |
| --- | --- | --- |
| 01-pass-four-qubit.json | n=4, K=2, d=2 | 规范正交；13/13；对角作用余数 (0,2)，模 4 |
| 02-fail-kl-four-qubit.json | n=4, K=2, d=2 | 规范正交；9/13；First failure 为 Z1，矩阵 [[0,0],[0,1]] |
| 03-unsupported-seven-qubit.json | n=7 | 导入时拒绝；原项目不变，不产生新的检查或认证结果 |

通过例：ψ0=(|0000⟩+|1111⟩)/√2，ψ1=(|0011⟩+|1100⟩)/√2。
失败例：ψ0 相同，ψ1=|0011⟩。二者都规范正交；第二例的 Z1 对角元不相等，因此 KL 失败。
失败例仍可有对角门作用，这与检测距离失败不矛盾。

七比特文件的预期英文报错为 `Qubit count must be an integer from 1 to 6.`。
“输入超出当前范围”与“数学对象不成立”必须区别。

四比特通过例应能计算，但右侧应说明没有对应 Lean adapter；Certificates 不能说当前输入
被 Class 36 旧证书认证。这是当前版本的明确功能边界，不是这一步应获得的 Lean 成功。

## A09 — 编辑器与错误输入

在四比特项目中打开 Edit full definition，将一个角度改成 -1，点击 Apply definition。
应出现英文范围错误，已应用的有效输入保持原样。点 Reset editor to current input 可撤销草稿。

再做一个合法 JSON 修改，但暂不点击 Apply definition。切到 Notebook 再回 Code，编辑草稿
应还在；此时点击 Run exact checks 或 Save project，应该要求先 Apply，不能悄悄运行旧定义。
注意：未 Apply 的原始文本目前不属于账户保存的项目，不要把关闭标签后的草稿恢复当作已支持。

## A10 — 保存冲突（建议测试）

在两个独立窗口 A、B 中载入同一个专用 QA 项目的同一已保存版本。
A 将笔记改为 `Window A edit` 并保存成功；B 在不重新载入的情况下改成 `Window B edit` 再保存。

B 应显示 `This project changed in another session...`，不能静默覆盖 A。
先导出 B 的草稿，然后 Reload saved project，应重新看见 A 的笔记。

## A11 — 实际运行本机 Lean（单独验收）

此项使用恢复后的标准 Class 36 项目；四比特例目前没有自动证明适配器。
在 Windows PowerShell 中运行：

```powershell
Set-Location 'D:\UTD\Project_purdue\Lean_certification'
python tools/sslp_service.py
```

保留该终端。若本机连接页已经能打开，无需重复启动第二个服务。
打开 http://127.0.0.1:8766/connect ，复制连接码；回原工作台，点击 Assistant，
把码粘贴到 Connection code，点击 Connect。这样保留原项目；必要时允许浏览器本地网络访问。
不要把连接码放进验收反馈或截图中。

先点击 Run exact check，应得到当前标准输入的 154/154；无需模型。
再点击 Run Lean verification。Queued、Running、Completed 只表示任务执行状态。
验收成功必须看见 Verification records 中 `Kernel check passed`，对应正确的提交输入哈希，
以及实际证明范围和公理记录。允许公理限于 Classical.choice、Quot.sound、propext。
下载本次任务报告和可用的验证包，保留作验收材料。

仅页面已有 archived certificate、模型说“通过”、任务 Completed，都不足以通过此项。
Failed / Timed out 应记录日志、错误和输入；不能解释成通过，也不能直接当数学反例。
默认单任务执行预算为 600 秒；依赖验证也占预算。环境不足应记“环境阻塞”，留待修复后复测。
页面右侧的 `Lean kernel: Not run in browser` 可能仍保留：它描述浏览器计算，真正本机结果在
Assistant 的 Verification records 中。统一项目与本机证明状态仍是后续任务。

## A12 — 研究助手（模型已配置时）

在连接后的 Assistant 中选择实际可用的本地模型；未配置的闭源选项不能作为可用模型验收。
先不勾选 Allow one Lean check，提交：

```text
Check the current code with the exact tool. Report normalization, the KL count,
and the first failing matrix if any. Cite actual tool records and state whether Lean ran.
```

检查英语回答、实际 tool calls 与 Verification records 是否一致。没有运行 Lean 时必须承认
Lean not run。还可用 Try an amplitude sign flip 验证助手能构造并检查候选，且不覆盖原输入。

若模型服务未安装或未启动，记为“模型环境未验收”，不要因此否定不依赖模型的计算和 Lean 功能。

## 结论标准与反馈

| 类别 | 判据 |
| --- | --- |
| 基础工作台验收 | A01–A09 可按说明完成；存储失败或错误数学结果不能算通过 |
| 保存冲突验收 | A10 阻止旧版本覆盖新版本 |
| 本机 Lean 验收 | A11 对实际输入产生新的、成功的内核验证记录 |
| 模型助手验收 | A12 工具调用、引用与解释一致 |
| 通用新码自动 Lean 认证 | 当前尚未实现，不能因本轮网页验收而标记完成 |
| 20260924 全文 formalization | 需另行做文稿陈述对应、内核构建及信任审计，本指南不代替该审计 |

以下任一项都应视为阻止该功能验收的缺陷：保存提示成功却丢数据；失败样例显示通过；
改变输入仍沿用旧结论；未运行 Lean 却显示该新输入已获 kernel certification；错误或不支持的
输入被静默替换为标准样例。

可直接按本目录 `验收记录模板.md` 填写。界面拥挤、配色、字体、定位失败项是否顺手也请记录，
这些属于产品体验验收；不要因为数学计算正确就忽略它们。

`expected-results.json` 是本地精确引擎对这批输入生成的期望摘要，包含 Class 36 改符号案例。
