# Results

## `axiom-audit.txt`

The output of `lake build SixQubit.Audit`, 528 lines, every one reading

```
'SixQubit.<Module>.<theorem>' depends on axioms:
  [propext, Classical.choice, Quot.sound]
```

This file is the **kernel dependency / axiom-footprint certification**. `#print
axioms` is transitive, so one clean line per headline theorem certifies its
entire dependency cone — every lemma, every `decide`, every
`linear_combination` beneath it. The absence of `Lean.ofReduceBool` is what
rules out `native_decide`.

It does **not**, by itself, show that a theorem targets the paper's intended
orbit or that every headline hypothesis is an admissible Knill--Laflamme row.
Those separate transcription obligations are checked by `gate.py`,
`momentgate.py`, `classify.py` and `admis.py`; see `tools/README.md`.

Regenerate and compare:

```sh
lake build SixQubit.Audit 2>&1 | grep "depends on axioms" \
  | sed 's/^info: [^ ]* //' | diff - results/axiom-audit.txt
```

No output means the stored audit is current.

A second, cheaper invariant catches a truncated or partially written file,
which a stray `tail` in an ad-hoc regeneration command will otherwise produce
silently:

```sh
test "$(grep -c '' results/axiom-audit.txt)" \n   = "$(grep -c '^#print axioms' SixQubit/Audit.lean)" && echo ok
```

Every axiom in every stored line must lie in
`{propext, Classical.choice, Quot.sound}`. It need not be all three:
`SixQubit.Orbit21Coef.coef_group_sum` prints `[propext]` alone, because a
`decide` over `Nat` masks needs no choice. A smaller footprint is a stronger
result, so the invariant is containment, not equality — a checker written to
compare against the three-axiom string would reject that theorem for being
too clean.

```sh
sed 's/^.*axioms: //' results/axiom-audit.txt | tr -d '[]' | tr ',' '
' \n  | sed 's/^ *//;s/ *$//' | grep -v '^$' | sort -u \n  | grep -vE '^(propext|Classical.choice|Quot.sound)$'   # must print nothing
```

Every `#print axioms` directive must contribute exactly one stored line, and
no stored line may still carry a `file:line:col` prefix — a `sed` that strips
only `info:` leaves one, and the result still looks plausible at a glance:

```sh
grep -c '[.]lean:' results/axiom-audit.txt   # must be 0
```

## `axiom-audit-codewrap.txt`

`SixQubit/CodeWrapAudit.lean` is a second, smaller audit module, covering the
three code-level wrappers `CodeWrap13`, `CodeWrap18` and `CodeWrap47`. Its
twenty lines were being printed by every build and read by nobody, because
nothing stored them and the documented command above only regenerates
`SixQubit.Audit`. They are stored here now, and the same two invariants apply:

```sh
lake build SixQubit.CodeWrapAudit 2>&1 | grep "depends on axioms" \n  | sed 's/^info: [^ ]* //' | diff - results/axiom-audit-codewrap.txt
```

## `orbit-table.tsv`

One row per certified orbit, generated by `tools/verification/mktable.py`.
The script parses `q` and `a` from each Lean module and cross-checks them against
`tools/manifest.json`; it takes `m` and `delta = q/m` from the manifest and
recomputes both fiber cardinalities from `(q, a, delta)`. The columns are orbit
id, modulus `q`, projective order `m`, angle vector `a`, residue offset `delta`,
both fiber sizes, Lean module, and its line and theorem counts. Totals: 51
orbits, 41,521 lines, 12,521 theorems.

(`Order9` predated the current conventions; it now carries an `av` definition like
every other module, so its `q`/`a`/`delta` cells are filled in and the acceptance
gate checks it like the rest.)

`delta` is taken from `tools/manifest.json`, where it is *defined* as `q/m` from the
paper's own 66-orbit table, and every module is checked against it by
`tools/verification/gate.py`.

This replaces an earlier and weaker rule. The original scan chose `delta` by fiber
size; a later pass added a polytope-dimension check but applied it only to the orbits
outstanding at that moment. Orbits 30, 53, 55 and 65 had already been certified and
were never re-checked, and all four turned out to use a residue of additive order two
rather than the order their projective order demands. A collaborator's audit found
this; all four have since been rebuilt at `delta = q/m`, and the correct fibers are
disjoint from the ones the old proofs used, so they are new proofs rather than
relabelled ones.

Fiber cardinalities in the table are COMPUTED from `(q, a, delta)`, not counted from
`def y`/`def z` declarations: several modules index the top fiber as
`SS.complement y_i` and declare no `def z` at all, which the earlier counting version
reported as a top fiber of size zero.

## `workflows/`

Records of the multi-agent passes used for the last two orbits: the scripts
(`*.js`) and the verdicts (`*-verdict.md`).

| Record | What it contains |
|---|---|
| `orbit26-verify-verdict.md` | the **adversarial review** that found a real gap in the first orbit-26 argument, with explicit witnesses satisfying every fact the argument used |
| `orbit26-rebuild-verdict.md` | the pre-checks and the cross-anchor repair |
| `orbit26-finish-verdict.md` | transcription and assembly |
| `orbit31-fam3-verdict.md` | the division-free form of the family-three relation, which closed the last gap |
| `orbit31-assembly-verdict.md` | branch assembly and the hypothesis audit |

These are kept for their **negative** content — which relations are not
available, which branches are vacuous, which counting arguments fail. Three of
the five reasoning errors in this project were assumptions of exactly that kind,
and rediscovering the refutations is far more expensive than storing them.

The agents were run under three standing instructions: verify by machine rather
than assert, actually compile rather than report compiling, and classify every
hypothesis of the headline theorem. The last one guards the failure mode that
matters most — a `False` theorem is only as good as its hypotheses, and an
algebraic fact smuggled in as an assumption is invisible from the outside. Both
final headlines were classified by hand afterwards:

| Orbit | Hypotheses | `offSum = 0` | `diagBot = diagTop` | `MomentSystem` | Other |
|---|---|---|---|---|---|
| 31 | 46 | 33 | 12 | 1 | 0 |
| 26 | 41 | 24 | 16 | 1 | 0 |

## The second batch of workflows

`remaining-11-record.md` and `orbit5-dichotomy-record.md` cover the multi-agent
passes that closed the twenty-two orbits added in `six_qubit_sslp.tex`.

| Record | What it contains |
|---|---|
| `remaining-11-record.md` | six mechanism groups (parity-four, spinor, phase propagation, projectors, trace, graph), each built and then **adversarially audited** by an independent agent |
| `orbit5-dichotomy-record.md` | three independent angles on the flip-kernel dichotomy that was the last open gap |

Two things in these records are worth reading rather than skipping.

**An audit that did not run caught nothing.** In `remaining-11`, the auditor for
the trace group hit a session limit. The orchestrator's own check then found that
`SixQubit.Orbit5.no_go_of_moments` did not exist at all — the module certified
real intermediate facts and said so honestly in its docstring, but the orbit was
still open. Without that check the batch would have been reported as complete
when it was not.

**Concurrent agents collided.** In `orbit5-dichotomy` three agents worked on the
same files; one agent's finished `Orbit5.lean` was overwritten by a peer's. The
displaced agent did not overwrite back — it parked its version and said so. Both
proofs survive: the installed one in `SixQubit/Orbit5.lean`, the other in
`alternatives/`. The lesson recorded here is that parallel attempts on shared
files need worktree isolation, which this run did not use.
